# Git Workflow

## Commit Hygiene: Agent-Session Artifacts

Some files in the workspace are **agent-session artifacts** — they support the development environment or agent tooling but are not part of the project source code (e.g. `.attachments/`, `.claude/`, `.playwright-mcp/`). Many of these are listed in `.gitignore`, but not all may be. Before committing, consider whether an untracked file is an agent-session artifact and exclude it even if `.gitignore` doesn't explicitly cover it.

Prefer explicit paths or `git add -u` over `git add .` / `git add -A` to avoid sweeping in files that should remain local. When in doubt, ask the user before staging. If a user explicitly asks for an agent-session artifact to be committed, consider moving it to a different directory.

## Shallow Clone Pitfalls

This workspace may be a shallow clone, which can cause two problems:

1. **Inaccurate branch comparisons** — the local base ref may not go back far enough to find the true common ancestor, making commit counts appear lower than they are.
2. **Silent rebase failures** — `git rebase` may only replay a handful of commits instead of the full branch history.

### Comparing Branches

Fetch the base branch first, then compare against the remote tracking ref:

```bash
git fetch origin <base-branch>
git log --oneline origin/<base-branch>..HEAD
```

Prefer `origin/<base-branch>` over the local ref to ensure accuracy.

## Rebasing

When the user asks to rebase, follow this **Backup → Rebase → Verify → Cleanup** pattern:

```bash
# 1. Ensure working directory is clean
git status --porcelain  # Must be empty — stash or commit any changes first

# 2. Create a timestamped backup branch
BACKUP="backup-before-rebase-$(date +%Y%m%d-%H%M%S)"
git branch "$BACKUP"

# 3. Fetch the base branch
git fetch origin <base-branch>

# 4. Rebase
git rebase origin/<base-branch>

# 5. Verify — commit count should look right, review diff for unexpected changes
git log --oneline origin/<base-branch>..HEAD
git diff "$BACKUP"

# 6. Clean up backup only after verification passes
git branch -D "$BACKUP"
```

If git can't find the common ancestor after fetching (e.g. a very old branch on a shallow clone), fall back to unshallowing:

```bash
git fetch --unshallow
git rebase origin/<base-branch>
```

### Handling Conflicts

```bash
# Check which files have conflicts
git status

# Edit files to resolve conflicts (look for <<<<<<< markers), then:
git add <resolved-files>
git rebase --continue

# To abort and restore from backup:
git rebase --abort
git reset --hard "$BACKUP"
```

If the intent of a conflict is unclear, use `git log --merge --oneline <file>` to see all commits from both sides that touched the file — the commit messages usually make the right resolution obvious without needing to ask the user.

### Compiled Assets (index.css, index.js)

Compiled/bundled assets are generated by `npm run build` and should **never be manually resolved** — their conflict markers are meaningless noise from two different builds. Accept `--ours` to satisfy git, resolve all other conflicts first, then rebuild to produce the correct output:

```bash
# Accept our side to satisfy git (the content will be overwritten by the build)
git checkout --ours <path/to/index.css> <path/to/index.js>
git add <path/to/index.css> <path/to/index.js>

# Resolve all other conflicts normally, then rebuild
npm run build

# Stage the freshly-built files and continue
git add <path/to/index.css> <path/to/index.js>
git rebase --continue
```

### Error Recovery

If something went wrong and the backup branch is gone:

```bash
git reflog
git reset --hard HEAD@{N}
```

### After Rebase: Summary and Force Push Prompt

The following rules only apply during rebase. Once the rebase and cleanup are complete, always:

1. **Summarize the result for the user.** Report:

   - How many commits are now ahead of the base branch
   - A brief description of what those commits contain (grouped by theme if possible)
   - The net diff stat vs the base branch (files changed, insertions, deletions)

2. **Ask whether to force push.** The rebased branch has rewritten history and must be force-pushed to update the remote. Ask:

   > The rebase is complete. Would you like me to force push to `origin/<branch>`? You may want to validate your changes first.

   Only force push if the user confirms. Use `git push --force-with-lease` (safer than `--force` — it refuses if someone else has pushed in the meantime):

   ```bash
   git push --force-with-lease origin <branch>
   ```
